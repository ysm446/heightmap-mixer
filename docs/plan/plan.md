## 決定済みの技術選定

| 項目 | 選択 |
| --- | --- |
| 言語 | C++20 |
| ビルド | CMake + vcpkg（manifest モード） |
| グラフィックス API | DirectX 12（SM 6.6、bindless） |
| シェーダ | HLSL / DXC（実行時コンパイル、ホットリロード） |
| UI | Dear ImGui（docking ブランチ） |
| 合成モデル | レイヤースタック（Quixel Mixer 風） |
| 対象 OS | Windows のみ |

導入済みの依存: DirectX-Headers, DirectX-Agility-SDK, D3D12MemoryAllocator,
WinPixEventRuntime, DirectXShaderCompiler, stb, Dear ImGui。
導入済み（M5a 時点）: tinyexr（EXR 読み込み）、nlohmann-json（プロジェクトの保存）。

## マイルストーン

### M0 — 基盤の立ち上げ（完了）
CMake + vcpkg のプロジェクト構成、Win32 ウィンドウ、DX12 デバイスと
スワップチェーン、フレームループ、Dear ImGui（docking）の統合、
デバッグレイヤーと PIX マーカー。

### M1 — RHI の整備（完了）
D3D12MemoryAllocator、ディスクリプタヒープアロケータ、アップロードリングバッファ、
遅延破棄キュー、PSO / ルートシグネチャのキャッシュ、
DXC によるシェーダコンパイルとホットリロード、bindless の全面採用。

### M2 — PBR プレビューレンダラ（完了）
**ここで「マテリアルが正しく見える」基準を確定させた。**

- **M2a**: グラフィックス PSO キャッシュ、深度バッファ、軌道カメラ、
  プリミティブ（球 / 平面 / キューブ）、GGX 直接光、HDR シーンカラー、
  EV100 露出、ACES トーンマップ、高 DPI 対応。
- **M2b**: IBL。HDRI 読み込み、equirect → キューブマップ変換、
  irradiance、prefiltered specular、BRDF LUT、スカイボックス表示。

### M3 — 合成エンジン v1（完了）

- **M3a**: レイヤースタックのデータモデル、GPU 評価器（タイル引数付き）、
  単色レイヤーとノイズによるハイト・マスク、ハイトブレンド、RNM、
  マスクのレベル調整と反転、評価結果をプレビューマテリアルへ直結、レイヤー UI。
- **M3b**: テクスチャレイヤー。画像の読み込みとテクスチャライブラリ、
  チャンネルごとのテクスチャ指定、マスクテクスチャ、ミップ生成。

### M4 — マスク生成（完了）

- **M4a**（完了）: ノイズの拡充（尾根状 / セル状 Worley）、
  **合成中間結果由来のマスク（高さ / 傾斜 / 曲率 / 窪み）**、マスクのカーブ。
  「窪みにだけ苔を生やす」「急斜面にだけ岩を出す」が書けるようになった。
- **M4b**（完了）: ペイントマスク（ブラシ）。
  メッシュ描画が書き出す**マテリアル UV バッファ**でカーソル位置を解決する。
  ブラシ半径は画面ピクセル指定、アンドゥは GPU 上のテクスチャコピー。

### M5 — アセットと入出力

- **M5a**（完了）: マテリアルライブラリ。PBR のマップ一式に名前を付けて持ち、
  レイヤーはマテリアルを 1 つ参照する。サムネイル、ファイル選択ダイアログ。
  チャンネルパック（Megascans の ORD）と EXR の読み込み。
- **M5b**（完了）: テクスチャパネル、プロジェクトの保存と読み込み、
  マテリアル単体の書き出し / 読み込み。形式は
  [reference/file-format.md](../reference/file-format.md) にまとめた。
  プロジェクトにはマテリアルの構造を丸ごと埋め込み、画像は相対パスの参照で持つ。
  ペイントマスクは手続きで再現できないので、サイドカーへ PNG で書き出す。
- **M5b-2**（完了）: 天球アセット。手続き的な空 / HDRI に名前を付けて複数持ち、
  ビューポートへ適用する。**空の輝度（HDRI の較正）と環境光の強さは天球ごと**に持つ
  （較正値はファイルごとに違うので、レンダラに 1 つ持つと差し替えのたびにずれる）。
  HDRI はテクスチャライブラリに入れず、天球アセットがファイルを直接参照する
  （equirect はマテリアルのマップとして使わないので、
  sRGB/リニアの 2 SRV・チャンネル SRV・ミップを作る意味がない）。
- **M5c**（完了）: フル解像度エクスポート。
  **書き出し専用の評価器を指定解像度で作り、タイルに分けて評価してから読み戻す。**
  プレビューの合成解像度には触らないので、編集中の見え方が変わらない。
  形式の変換とチャンネルの詰め替えは `ExportPack.hlsl` が GPU 側でまとめて行い、
  CPU は「並べれば PNG になるバイト列」だけを受け取る。
  パッキングは 個別 / ORD（Megascans）/ ORM（glTF・Unreal）。
  ハイトは EXR（float）で出す。8bit の PNG では段差が見えるため。
- **M5d**（次）: 配布形態（シェーダの同梱方法）の見直し。

### M6 — レイヤーの種類（サーフェス / シェイプ / リキッド）（完了）

Quixel Mixer の Surface / Noise / Liquid に相当する分類を入れ、
**高さの合成規則をレイヤーの種類ごとに分ける**。スタックは 1 本のまま、
順序の意味（下から積む）も変えない。

- **サーフェス**: 既存の `MaterialLayer` そのもの。高さ + マスクの競合（変更なし）。
- **シェイプ**: 下地の高さへの**加算**。`h += (src - 0.5) × 起伏の強さ × マスク`。
  置き換えではなく加算なので、下のサーフェスレイヤーの細部が保存され、
  地形スケールの大きな形を作れる（M7 地形の下準備でもある）。
  法線は自分の勾配から作った法線をマスクぶん弱めて RNM で重ねる
  （加算した高さと辻褄を合わせる）。BaseColor / Surface は書かない。
  **加算後の Height は 0〜1 へクランプする。**
  高さ競合・高さ由来マスク・リキッドの水位・PNG 書き出しがすべて 0〜1 を
  前提にしており、起伏の実寸はディスプレイスメントの強さが担うので、
  データ側のレンジを広げる意味がない。
- **リキッド**: 絶対値の水位を持ち、下地が水位より低い所だけ高さを水位へ置き換える。
  重みは「水位 − 下地の高さ」だけから決める（細いフェザー付き。
  `HeightBlendWeight` は通さない）ので、**水位を動かしても下地は変形しない**。
  「水位 − 下地」= 深さがここで手に入るため、吸収（深いほど濃い色）などの
  水の表現はこの延長に置く。質感の推奨値は暗い青緑 + 低ラフネス + メタリック 0。
- ファイル形式は版上げし、旧ファイルは全レイヤーをサーフェスとして読む。
- レイヤーの追加 UI を種類別に分ける（Mixer の Add Surface / Noise / Liquid と同型）。

### M7 — 地形
ハイトマップインポート（16bit PNG / RAW / EXR）、LOD 付き地形描画、
マテリアルのスプラット適用、地形属性を M4 のマスク入力へ接続、地形ペイント。

## 開発用のコマンドライン

```
material_mixer.exe [--project <path>] [--save-project <path>]
                    [--hdri <path>] [--texture <path>]...
                    [--export <dir>]
                    [--screenshot <path>] [--screenshot-ui <path>]
                    [--screenshot-frame <n>]
```

`--texture` は繰り返し指定でき、起動時にテクスチャライブラリへ読み込む。

`--project` は起動時にプロジェクトを開く。`--save-project` は数フレーム描いてから
プロジェクトを保存して終了する。対話せずに保存と読み込みを往復させて確かめるための開発用。

`--export` は数フレーム描いてから合成結果を画像へ書き出して終了する。
書き出しの設定は書き出しウィンドウの既定値（2048、個別、全マップ）を使う。

`--screenshot` はビューポートの内容を、`--screenshot-ui` は UI 込みの
ウィンドウ全体を PNG に書き出して終了する。
画面キャプチャに頼らず結果を確認できるため、リモート環境や自動確認で使う。

## 判断を保留している点

- 地形 LOD の方式（CDLOD / ジオメトリクリップマップ / GPU 駆動クアッドツリー）は
  M7 着手時に決める。
- レイヤー内部のマスク生成をノードグラフ化するかは、M5 以降に改めて判断する。
  M4 で「ノイズ / 中間結果 / テクスチャ / ペイント」が揃い、
  当面はこの 4 つの組み合わせで足りている。
- リソース状態の管理単位。現在はリソース全体で 1 つしか持たない
  （ミップ連鎖の生成だけ例外的にサブリソース単位）。
  ミップごとに別状態へ遷移させたい場面が増えたら本格対応する。
- 自動露出と AgX トーンマップ。必要になった時点で追加する。
- パララックスとシャドウ。ハイトチャンネルが揃ったので実装可能だが、
  M4 のマスク生成を優先する。
