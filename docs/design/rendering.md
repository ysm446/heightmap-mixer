# rendering — PBR プレビューの設計

作成日時: 2026-08-31 12:09
更新日時: 2026-09-01 08:10

`src/renderer/` の設計方針。M2a（直接光）と M2b（IBL）で確定し、
M4b でマテリアル UV バッファを足した。

## 描画の流れ

```
シーンカラー(RGBA16F, 線形) + マテリアル UV(RGBA16F) + 深度(D32)
    ↓  メッシュ描画（GGX 直接光 + IBL。露出は掛けない。MRT で UV も書く）
    ↓  スカイボックス（深度書き込みなし、LESS_EQUAL で残った画素を埋める）
    ↓                （UV バッファには書かないので、シーンカラーだけ束ね直す）
シーンカラー
    ↓  トーンマップパス（コンピュート）: 露出 → トーンマップ → sRGB
表示用テクスチャ(RGBA8_UNORM)
    ↓
ImGui のビューポートパネルへ表示
```

**シェーディングは絶対放射輝度のまま出力し、露出はトーンマップパスでのみ掛ける。**
こうすることで、ライトの照度（lux）とカメラの露出設定を独立に扱える。

## マテリアル UV バッファ

メッシュ描画は 2 枚目のレンダーターゲットへ `frac(uv * materialUvScale)` と
被覆フラグを書き出す。ペイントのブラシが
「画面のこの画素はマテリアルのどこか」を引くために使う。

- **スカイボックスは 1 枚目だけに描く。** PSO のレンダーターゲット数が変わるため、
  メッシュのあとに `OMSetRenderTargets` でシーンカラーだけを束ね直す。
- **クリア値はリソース生成時の値と揃える。** UV バッファは被覆 0 でクリアするので、
  `TextureDesc::clearColor` のアルファも 0 にしてある。ずれるとデバッグレイヤーが警告する。
- 用途と精度の理由は [compositing.md](compositing.md) のペイントマスクの節にある。

## 露出とトーンマップ

物理カメラベースで統一する。

```
EV100    = log2(N^2 / t) - log2(ISO / 100)
exposure = 1 / (1.2 * 2^EV100)
```

- マニュアル露出（絞り / シャッター / ISO、または EV 直接指定）。
- トーンマップは ACES（Stephen Hill のフィット）を既定とし、Reinhard となしを切り替えられる。
- 環境の輝度は絶対値（cd/m^2 相当）で持ち、露出と独立に扱う。

参考値。晴天の直射日光がおよそ 100000 lux、晴天の空が 4000〜15000 cd/m^2。
手続き的な空の既定値はこれに合わせてある。暗くしすぎると日中の露出で黒く潰れる。

### HDRI は較正してから使う

**HDRI ファイルは絶対輝度で較正されていない。** Radiance 形式は `EXPOSURE=` ヘッダで
較正値を持てるが、合成ツールが出すものはまず持たない（`stb_image` も読み飛ばす）。
実測すると、Poly Haven 系の屋外 HDRI は**空が 0.15〜0.2** 程度だった。

生の値のまま使うと、日中の露出（EV100 ≈ 16、露出係数 1.3e-5）で
`0.2 x 1.3e-5 = 0.0000026` となり**真っ黒になる**。3 桁以上ずれている。

そこで、**読み込み時に空の代表輝度を測り、指定した cd/m^2 に合わせる倍率**を掛ける。

- 分母は `MedianSkyLuminance()`（上側 40% の**中央値**）。
  平均だと太陽に引きずられる（実測で最大は空の 2000 倍以上あった）。
- 分子は UI の `空の輝度`（既定 12000 cd/m^2 = 晴天）。
- **倍率そのものをユーザーに指定させない。** ファイルによって空の値が違うので、
  同じ倍率でも結果が変わってしまう。「空が何 cd/m^2 か」ならどのファイルでも同じ意味になる。

**画像内の比は本物なので、定数倍しても物理的な関係は壊れない。**
足りないのは絶対値の基準だけで、それをここで与えている。

手続き的な空は `EnvSky.hlsl` が最初から cd/m^2 で書き込むため、較正は掛けない（倍率 1.0）。

未実装: 自動露出（輝度ヒストグラムから EV を決めて時間補間）、AgX。

### 影（シャドウマップ）

ディレクショナルライトの影を落とす（`ライティングと露出 > 影`）。

- ライトから深度だけを 2048^2 の深度テクスチャへ描き、本描画で比較する。
  深度は `R32_TYPELESS` で作り、DSV は `D32_FLOAT`、SRV は `R32_FLOAT` を張る。
- 投影は**平行投影**。プレビューの被写体（半径 2.2 の範囲）だけを覆えばよい。
- **比較サンプラは使わない。** 普通の `Texture2D<float>` として読み、3x3 の
  ポイントサンプルを平均する。ルートシグネチャに比較サンプラを足さずに済む。
- 自己遮蔽（シャドウアクネ）対策は、傾きに応じて増やす下駄だけ。
  ライトに対して斜めなほど大きくする。
- **影は直接光にだけ掛ける。** 環境光（IBL）には掛けない。
- シャドウパスは本描画と**同じ頂点シェーダ・同じ分割**で描く。
  形が違うと自分の影が自分に落ちて縞になる。

### テセレーション

`プレビュー設定 > テセレーション`。**画面上の辺の長さ**で分割量を決める。

- ハルシェーダが各辺を画面へ投影し、1 辺がおよそ 10 ピクセルに収まるよう
  分割数を決める（上限は UI の `分割の上限`）。**細かいメッシュではそのまま 1 になり、
  寄って 1 辺が伸びたときだけ細かく割る。**
- ドメインシェーダで重心座標の補間と**ディスプレイスメント**を行う。
  式は頂点シェーダと共通の `ApplyDisplacement`（`MeshPbr.hlsl`）で、
  どちらも**ワールド空間**で適用する。別々に書くと、モデル行列を入れたときに
  テセレーションの ON / OFF で形が変わってしまう。
- **分割量はカメラから見た値で決め、シャドウパスでも同じ値を使う**
  （`tessellationViewProjection`）。パスごとに分割が変わると形がずれて影が破綻する。
- 出力トポロジは `triangle_cw`。右手系 + `FrontCounterClockwise = TRUE` の組み合わせでは
  こちらが表になる。`triangle_ccw` にすると裏面だけが見えて真っ黒になる。

### ディスプレイスメント

合成した Height を**頂点で押し出して形状に反映する**（`変位量` が 0 なら何もしない）。

- 頂点シェーダが Height を `SampleLevel` で読み、法線方向へ `(h - 0.5) * 変位量` 動かす。
  **0.5 を基準にする**のは、全体が膨らんだり縮んだりしないようにするため。
- 頂点シェーダには微分が無いので `SampleLevel`（ミップ 0）を使う。
- **押し出せる細かさは頂点の密度で決まる。** プレビューのメッシュはそのために細かく割ってある
  （球 256x128 / 平面 256 分割 / キューブは 1 面 96 分割）。
- **法線は作り直していない。** 合成の Normal はもともとハイトの勾配から作っており、
  同じ凹凸を表しているので、そのまま使える。ただし変位量を大きくすると
  「形にも出て、法線にも出る」二重掛けになるので、レイヤーの `法線の強さ` を下げる。
- テセレーション（HS/DS）を使うと、分割後の点でも同じ式で押し出される
  （上の「テセレーション」を参照）。

### 表示モード

ビューポートには合成したチャンネルをそのまま出せる（`renderer::DebugView`）。

- メッシュのピクセルシェーダが、シェーディングの代わりにチャンネルの値を書く。
- `TonemapPass` は `debugView != 0` のとき**露出・トーンマップ・sRGB 変換を通さない**。
  データを見るための表示なので、値をそのまま画面へ出す。
- 背景（スカイボックス）も描かない。
- C++ の `DebugView` と HLSL の `MM_VIEW_*` は並びを一致させること。

### レンズ（画角）

**UI では画角を焦点距離 (mm) で指定する。** 露出を絞り / シャッター / ISO で
決めている以上、レンズだけラジアンで扱うと言葉が揃わない。

```
焦点距離 = (センサー高 / 2) / tan(縦画角 / 2)      センサー高 = 24mm（35mm フルサイズ）
```

- 内部（`Camera::FovY()`、プロジェクトファイル）は**ラジアンのまま**持つ。
  換算は `renderer::FocalLengthFromFovY` / `FovYFromFocalLength` で UI 側だけが行う。
- 縦画角を基準にする。ビューポートの縦横比は表示サイズで変わるため、
  横を基準にすると同じレンズでも画角が変わってしまう。
- 既定は 29mm（= 縦 45 度）。

## IBL

分割和近似。生成はすべてコンピュートで、`Device::ExecuteImmediate` により
環境の読み込み時に一度だけ走る。

```
equirect (RGBA32F)
    ↓  EnvEquirectToCube
キューブマップ 256^2 (RGBA16F, ミップ付き)
    ↓  EnvDownsample（ミップ連鎖）
    ├→ EnvIrradiance   → irradiance キューブ 32^2
    └→ EnvPrefilter    → プリフィルタ済みキューブ 128^2（ラフネス別に 6 ミップ）
EnvBrdfLut → 環境 BRDF の LUT 256^2 (RG16F)
```

- **irradiance マップには `E / pi`**（余弦重み付きの平均放射輝度）を格納する。
  シェーディング側は `diffuseColor` を掛けるだけでよい。pi を二重に割らないこと。
- プリフィルタはサンプルの立体角に応じたミップから引き、ファイアフライを抑える。
  そのためにキューブのミップ連鎖が要る。
- **手続き的な空に太陽は入れない。** 太陽はディレクショナルライトで扱う。
  環境マップに入れると二重計上になり、256^2 のキューブでは
  エイリアスとファイアフライの原因になる。

キューブマップの面の並びは D3D の規約に従う（0: +X, 1: -X, 2: +Y, 3: -Y, 4: +Z, 5: -Z）。

## ラフネスの下限

知覚ラフネスは全経路で **0.045 を下限**にクランプする
（`Brdf.hlsli` の `kMinPerceptualRoughness`）。

- 適用箇所: 直接光（`MeshPbr`）、サムネイル（`MaterialThumbnail`）、
  BRDF LUT の生成（`EnvBrdfLut`）。
- 理由は 2 つ。
  1. 0 に近づくと GGX の D 項が発散し、RGBA16F のシーンカラーに Inf が出る
     （half の上限 65504 を超える）。
  2. `alpha^2 = roughness^4` が fp16 で表現できる範囲を割って 0 に潰れる。
     0.045 は `0.045^4 ≒ 4.1e-6` で、fp16 の正規最小値（6.1e-5）は割るが
     非正規域で表現でき、演算が 32bit の限り安全に持ち上がる値として
     Filament / Frostbite が採用している。**独自の値を作らず、これに合わせる。**
- プリフィルタ済みキューブのミップ 0 だけは例外で、**roughness = 0 の鏡面**を
  そのまま焼く（`EnvPrefilter` の特別扱い）。シェーディング側は下限未満の
  ラフネスを参照しないため、ミップ 0 はミップ 0.36 付近からの三線形補間の
  一端としてしか使われない。

## 座標系

**右手系 Y-up。** X が右、Y が上、Z が手前（画面から見て奥が -Z）。
terrain-editor と同じ規約に揃えてある。

- ビュー行列は `XMMatrixLookAtRH`、投影は `XMMatrixPerspectiveFovRH`。
  **LH 版を使うと画面が左右反転し、+X が画面左に出る。**
  対称なプリミティブでは気づきにくいので、規約側で固定しておく。
- 深度の範囲は RH 版でも `[0, 1]`（D3D の規約）。クリアは 1.0、比較は LESS_EQUAL。
- カメラの基底は `右 = 前 × 上`。`Camera::Basis()` がビュー行列と同じ基底を返す。
- ライトの方位角は 0 度が +Z、90 度が +X。仰角は +Y 方向。

**外向きの面は画面上で反時計回りに見える。** ラスタライザは
`FrontCounterClockwise = TRUE` で固定する。LH のままの設定
（`FALSE`）を残すと、すべての面が裏面判定になって消える。

ワールド空間そのものは手系に依らない。キューブマップのサンプルも
法線・タンジェントもワールド空間の向きで扱うので、ここは変わらない。

## 行列の規約

DirectXMath は行ベクトル規約、HLSL の定数バッファ内の行列は既定で列優先。
`XMMATRIX` をそのまま積むと HLSL 側では転置として解釈されるため、
`mul(matrix, vector)` が意図どおりに動く。**転置は入れない。**

法線行列だけは `(M^-1)^T` が必要なため、`XMMatrixTranspose(XMMatrixInverse(...))` を積む。

## メッシュ

球 / 平面 / キューブをコード生成する。頂点は position / normal / tangent / uv。

**球だけ添字の並べ方が逆になる。** 球は行方向が -Y、列方向が経度なので、
平面やキューブと同じ並べ方をすると外向き面が裏面判定になる。
誤ると遠側の内面が見え、暗く巨大な面が映る。
生成後はどれも「外向き = 反時計回り」に揃うので、カリングの設定は 1 つで足りる。

## 高 DPI

`ImGui_ImplWin32_EnableDpiAwareness()` はウィンドウ生成前に呼ぶ。
呼ばないと Windows にウィンドウごと拡大され、描画解像度が半分になってぼやける。
テクスチャを等倍で見たいツールとしては致命的。

- フォントサイズとスタイルを DPI スケールで拡大する。
- 初期ウィンドウサイズも DPI で拡大し、`Window::Create` で実際に載ったモニタの
  作業領域に収める。`SPI_GETWORKAREA` はプライマリモニタしか見ないので使わない。

## ImGui のビューポート

**`ImGui::Image` は入力を消費しない。** 画像の上でドラッグすると
「ウィンドウの余白のドラッグ」と解釈され、パネルごと動いてしまう。
同じ矩形に `InvisibleButton` を重ねてドラッグを受け止めること。
併せて `io.ConfigWindowsMoveFromTitleBarOnly = true` を入れてある。

画像はテクスチャの実サイズではなくコンテンツ領域に合わせて描く。
実サイズで描くとパネルからはみ出し、スクロールバーの出入りで要求サイズが振動する。
レンダーターゲットの作り直しは 1 フレーム遅れる。
